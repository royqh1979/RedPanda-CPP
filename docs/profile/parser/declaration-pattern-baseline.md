# 声明期特化模式范围的性能对照

## 场景

该对照用于决定特化匹配模式是只保留外层结构，还是递归保存全部嵌套结构。

- Direct Release，独立进程连续运行三次，取中位数。
- Parse 输入：`#include <bits/stdc++.h>` 的完整解析。
- Eval 输入：`unordered_map.find("key")->second`。
- 工具链：GCC 15.3 与 GCC 8.1；不同工具链的内部声明结构不同，不直接比较调用次数。

## 结果

| 阶段 | GCC 15.3 parse | GCC 8.1 parse | eval |
| --- | ---: | ---: | ---: |
| 声明模式改造前 | 1208 ms | 859 ms | 8.55 ms |
| 仅外层模式 | 1206 ms | 875 ms | 7.26 ms |
| 递归嵌套模式 | 1210 ms | 881 ms | 7.22 ms |

外层模式的 eval entry 数从 193 降为 109，耗时约降低 15%。递归模式的 entry 数进一步降为 78，但 eval 仅再改善约 0.5%，已处于测量噪声范围，同时 GCC 8.1 parse 又增加约 6 ms。

## 结论

当前实现只保留外层模式。递归嵌套结构化不纳入实现；entry 数不能代替真实收益。若未来重新评估，必须同时比较完整 parse 成本、实际 eval 收益和正确性，而不是仅看匹配调用次数。
