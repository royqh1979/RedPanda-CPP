# QSynEdit 块注释折叠设计

## 1. 目标与范围

为 C/C++ 的多行 `/* ... */` 和 `/** ... */` 注释提供折叠，复用现有 SyntaxState、CodeBlock、增量重扫、显示映射和编辑展开机制。

本功能只增加块注释折叠，不折叠连续 `//` 行，不改变自动缩进和语法高亮规则。

## 2. 为什么不能按整行文本判断

以下一行可以同时包含旧注释的结束和新注释的开始：

```cpp
*/ int value; /* comment
```

仅检查 `*/`、`/*` 或结束行文本，无法确定折叠块边界，也无法区分多个注释与代码块。必须从 Syntaxer 在字符扫描过程中产生有序事件，不能使用行级文本猜测或后置补丁。

## 3. 有序事件与块类型

在共享类型定义中增加 `CodeBlockKind`，至少区分：

- `Code`：现有花括号和预处理范围；
- `Comment`：`/* ... */` 及其 Doxygen 形式。

`BlockDelimiterEvent` 在现有 `ch/started` 外携带 `kind`，默认值为 `Code`，既有花括号事件不需要机械改写。事件相等比较必须包含 `kind`。

`CodeBlock` 同样保存 `kind`。折叠扫描创建块时从 Open 事件复制类型；Close 只关闭当前栈顶块，并沿用该块类型。折叠状态缓存键由 `(fromLine, toLine)` 扩展为 `(kind, fromLine, toLine)`，避免相同行范围从代码块变成注释后错误继承 collapsed 状态。

注释事件不改变 `blockLevel`，也不复用 `blockStarted/blockEnded` 计数：这些字段参与现有代码块和缩进配对，注释混入会改变 `}` 的处理。注释只进入有序 `blockEvents`。

新增行或状态失效判断必须检查完整 `blockEvents`，不能只检查花括号计数，否则含注释的新行可能不会触发折叠重扫。

## 4. Syntaxer 事件位置

- `procSlash()` 确认读到 `/*` 时，在 `/` 的位置发出 Comment Open，然后沿用现有注释状态迁移；`#define` 和续行预处理入口也必须在同一位置发出相同事件；
- 普通块注释和 Doxygen 注释确认读到 `*/` 时，在 `*` 的位置发出 Comment Close，再沿用现有状态迁移；
- 字符串、字符字面量和 `//` 注释中的标记不经过这些入口，因此不产生事件；
- 同一行的事件按实际扫描顺序保存。

例如：

```cpp
/* first
*/ int value; /* second
continued
*/
```

第一行产生 Comment Open；第二行先 Close 第一个注释，再 Open 第二个注释；第四行 Close 第二个注释。不能因第二行含 `*/` 就把它统一当成某个代码块或另一个注释的结束。

C/C++ 不支持嵌套块注释，因此注释内部的 `/*` 不再产生 Open；第一个 `*/` 按现有语言规则结束注释。

## 5. 折叠范围与嵌套

多行注释和代码块共用现有栈式扫描：

- 函数内的多行注释成为该函数折叠块的子块；
- 注释内的 `{`、`}` 被 Syntaxer 忽略，不干扰代码配对；
- 注释结束后的代码继续正常配对；
- 同行注释不产生实际可隐藏行，沿用现有 same-line block 清理规则；
- 未闭合注释沿用现有未完成块规则延伸至 EOF，后续编辑补全后可正常重扫。

## 6. 结束分隔符长度

现有代码默认结束符为单字符 `}`，注释的结束符 `*/` 长度为 2。必须由一个统一的位置换算规则处理两种类型，不能在各调用点散写修正：

- `toCh` 始终指向结束分隔符首字符，即 `}` 或 `*`；
- 结束符后的真实位置为 `toCh + endDelimiterLength`；
- 结束行是否存在后缀，按结束符后的位置与真实行长度比较，不 trim；
- 折叠虚拟光标映射到 Document 时，也使用该位置。

所有现有 `toCh + 1` 的显示、编辑和光标路径都要统一替换为该规则。

## 7. 折叠显示

不改变 Syntaxer 的 `foldString()` 接口。QSynEdit 已持有带类型的 CodeBlock，可直接选择占位符：

- Comment 且结束行隐藏：`...*/`；
- Comment 且结束行因后缀可见：`...`；
- Code：继续调用现有 Syntaxer 路径，保持 `...}` 和预处理行为。

Comment 占位符使用 `commentAttribute()`，Code 占位符使用 `symbolAttribute()`；原子光标单位、行宽、鼠标定位和编辑展开继续复用现有公共路径，不为注释另建一套显示或编辑算法。

## 8. 编辑与增量重扫

沿用现有折叠编辑规则：

- 编辑注释折叠范围内的隐藏内容前展开当前视图；
- 只修改 Open 前或 Close 后的内容且后缀可见性不变时，不必展开；
- 后缀从有到无或从无到有时按现有规则展开并重建显示状态；
- 整行删除/替换、Undo/Redo、多视图各自 collapsed 状态和批量 DocumentChange 合并规则不变；
- 增量重扫与全量重扫必须产生相同的类型、范围和字符位置。

## 9. 测试清单

### 基础识别

- 普通多行注释和 Doxygen 多行注释；
- 单行注释不产生可隐藏范围；
- 同一行多个注释，以及 `*/ ... /*` 的关闭/开启顺序；
- 注释内花括号、字符串或字符字面量中的注释标记、`//` 中的注释标记；
- 注释位于函数内、函数包含注释、注释前后仍有代码；
- 未闭合注释及补全后的重扫。

### 显示与光标

- Close 后无后缀：隐藏结束行并显示 `...*/`；
- Close 后有空格、Tab、分号或代码：结束行可见并显示 `...`；
- 占位符宽度、行映射和鼠标定位；
- 虚拟 `*/` 后位置与真实 Document 位置双向映射，不停留在两个字符之间。

### 编辑与状态

- 注释内部编辑展开，Open 前和 Close 后编辑按后缀规则处理；
- 插入、删除、修改分隔符后，增量结果与全量重扫一致；
- 同行 Close/Open 场景下各块的 collapsed 状态不混淆；
- Undo/Redo 和共享 Document 多视图；
- 现有花括号、预处理折叠测试全部保持通过。

## 10. KISS 与范围审核

只需要一种新增块类型和一条结束符长度规则，不需要独立 CommentFold 类、额外全文扫描或新的 Syntaxer 对外接口。事件由现有字符扫描自然产生，后续全部复用通用 CodeBlock 路径。

实现时不得通过整行正则、后缀文本猜测或强制修改 `blockStarted/blockEnded` 来绕过类型和顺序问题。
