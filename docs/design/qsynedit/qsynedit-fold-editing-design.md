# QSynEdit 折叠显示、光标与编辑规则方案

## 1. 目标

修复折叠显示与编辑之间的不一致：

- 折叠后不能丢失实际 `}` 同行的后续内容。
- `} else {` 不再作为独立的行号特判。
- 折叠占位符使用正常 Symbol 颜色，不绘制额外的折叠行下划线。
- 光标可以按明确规则经过折叠占位符，但不能停在省略号中间。
- 编辑隐藏内容前必须展开；仅编辑折叠块外部且不改变折叠显示状态时，不必展开。
- 文档内容、光标位置、折叠状态和 Undo/Redo 必须保持一致。

本方案针对既有行为的系统性调整，不保留与最终规则冲突的临时虚拟光标实现。

## 2. 折叠块需要记录的源位置

`CodeBlock` 继续以 `fromLine/toLine` 表示实际 `{` 和匹配 `}` 所在的源代码行，并增加：

- `fromCh`：起始 `{` 在 `fromLine` 中的字符位置；
- `toCh`：匹配 `}` 在 `toLine` 中的字符位置；未完成块使用无效位置。

`toLine` 始终是实际 `}` 所在行，不再因为同一行随后出现 `{` 而改成上一行。

### 2.1 折叠扫描必须保留有序分隔符事件

当前逐行 `blockStarted/blockEnded` 计数不足以恢复字符位置，也不足以表达同行事件的先后顺序。应在每行 SyntaxState 中保留按源码顺序排列的分隔符事件：

```text
(ch, Open/Close)
```

扫描折叠块时按事件顺序处理：

- Open 创建子块并记录 `fromLine/fromCh`；
- Close 关闭当前块并记录 `toLine/toCh`；
- 同行 `} else {` 先关闭旧块，再创建新块；
- 同行多个块和嵌套块均按同一算法处理。

实现时必须同步检查：

- `setLine()` 清空本行旧事件；
- `{`/`}` 处理函数同时更新事件和既有计数；
- `SyntaxState::equals()` 比较完整有序事件；
- 增量重扫不能只比较每行 Open/Close 数量，否则同行位置变化会留下失效的 `fromCh/toCh`；
- 保留、移动、失效和增量重建 CodeBlock 时，字符位置随实际内容更新。

预处理折叠没有花括号位置，继续使用行范围，不参与 `}` 尾部规则。

## 3. 结束行可见性与折叠显示

对已完成且包含花括号的折叠块，直接根据当前文档判断：

```text
hasEndLineSuffix = toCh + 1 < lineText(toLine).length()
```

这里不 trim：空格、Tab、注释和分号都属于内容。

### 3.1 `}` 后没有任何字符

- 隐藏 `fromLine + 1` 到 `toLine`；
- 起始行追加 `...}`；
- 结束行不直接显示。

### 3.2 `}` 后存在字符

- 隐藏 `fromLine + 1` 到 `toLine - 1`；
- 起始行追加 `...`；
- `toLine` 完整显示，包括真实的 `}` 和后续全部字符。

因此：

```cpp
if (ok) {
    work();
} else {
    other();
}
```

折叠第一个块后，真实的 `} else {` 行仍然可见，不需要额外的 `started > 0` 特判。

### 3.3 共用显示映射

以下路径必须使用同一个折叠显示函数：

- Painter 的文本和 token 绘制；
- 行宽和水平滚动范围；
- 鼠标定位；
- 光标坐标；
- 左右移动和选区扩展。

占位符是显示内容，不进入 Document，不参与文件保存、搜索或普通文本复制。

折叠占位符使用 Symbol 属性，不使用异常 token 属性，也不套用彩虹括号颜色。折叠后不额外绘制整行下划线。

### 3.4 无可隐藏内容

`fromLine == toLine`，或结束行可见且 `toLine == fromLine + 1` 时，没有任何源代码行被隐藏。此时折叠不改变文本显示，不产生虚拟光标位置，也不追加占位符。

## 4. 光标规则

### 4.1 占位符是原子单位

光标不能停在 `...` 的字符之间。鼠标点击占位符时，选择距离最近的合法端点。

### 4.2 结束行隐藏：`...}`

保留一个虚拟位置，表示实际 `}` 之后：

- 从起始行真实行尾按右键，到虚拟 `}` 后；
- 从虚拟 `}` 后按左键，回起始行真实行尾；
- 从下一可见行按左键，到虚拟 `}` 后；
- 从虚拟 `}` 后按右键，到下一可见行；
- 不允许其它占位符内部位置。

虚拟位置只用于视图光标和选区端点。需要访问 Document 时，必须映射为 `CharPos{toCh + 1, toLine}`。

### 4.3 结束行可见：`...`

不引入虚拟 `}`：

- 从起始行真实行尾按右键，到结束行；
- 从结束行行首按左键，回起始行真实行尾；
- 结束行内的光标移动与普通文本相同。

### 4.4 隔离文档位置与虚拟光标位置

`validInDoc()` 继续只接受真实文档位置，不得为了折叠光标而接受超出真实行长的 ch。

应单独提供光标专用校验和规范化：

- 真实文档位置按普通 glyph 边界校验；
- 虚拟位置仅允许上述 `}` 后位置；
- Caret/Selection 的内部设置使用光标专用校验；
- Document 的读取、写入、搜索范围和撤销位置仍使用真实位置；
- 编辑前必须把虚拟选区端点映射到实际 `toCh + 1/toLine`。

## 5. 编辑规则

### 5.1 复用 DocumentChange，逐视图处理

不新增独立的编辑上下文，也不从 Undo 反向推断编辑。现有 DocumentChange 直接携带：

```text
修改类型和行范围：kind / line / count
实际字符范围：startCh / endCh
是否属于整行修改：wholeLine
```

`recordChange()` 仍负责按既有规则合并相邻修改。`putLine()` 在替换前行文时记录旧文本中的受影响字符范围；整行标记根据实际覆盖范围产生，不使用带默认值的接口参数掩盖调用差异。

每个视图在自己的 `onDocumentContentChanged()` 中处理每条 DocumentChange：

- 使用该视图自己的 collapsed 状态、折叠块位置和旧尾部状态；
- 必要时只展开当前视图，不能假定其它视图具有相同折叠状态；
- 展开发生在 fold 移动、fold rescan、行映射、布局和绘制之前；
- 展开本身不生成 Undo 项，Undo 仍只负责撤销记录。

虚拟 `}` 后的光标在编辑命令执行前映射到真实 `toCh + 1/toLine`，使既有编辑命令能够正常执行；折叠展开决策仍在 DocumentChange 到达时完成。

### 5.2 基本矩阵

| 场景 | 处理 |
|---|---|
| 编辑 `{` 后、`}` 前或折叠块内部 | 先展开 |
| 删除 `{`，或 Backspace 删除 `}` | 先展开 |
| 完全位于 `{` 前的插入、删除或替换 | 不展开 |
| 仅在 `}` 后插入或向后删除，且尾部内容存在性不变 | 不展开 |
| 选区或结构编辑与折叠块任意部分相交 | 先展开 |
| 删除前行行尾回车并接到 `{` 所在行 | 不展开，因为编辑完全位于 `{` 前 |
| 整行删除或整行替换 | 不展开，见 5.4 |

对隐藏结束行的虚拟 `}` 后编辑，先映射到真实 `toCh + 1/toLine`，再适用上述规则。

### 5.3 尾部内容存在性变化

必须根据编辑后的结果判断，不能只看编辑前内容：

- 原来无尾部内容，编辑后新增内容：先展开；
- 原来有尾部内容，编辑后仍有内容：可以不展开；
- 原来有尾部内容，编辑后删光：先展开；
- Backspace 删除实际 `}`：无论尾部状态如何都先展开。

判断新增文本时只看第一个换行符之前的内容；换行本身不等于在实际 `}` 后新增同行内容。

删除尾部内容时，应计算删除后实际剩余的同行后缀。不能在删光后让结束行突然隐藏并吞掉当前光标。

### 5.4 整行删除/替换例外

例外只适用于操作本身已经完整覆盖目标源代码行的情况，不能仅凭命令名称跳过展开。

折叠起始行在显示上代表整个折叠块。对该行执行折叠状态下的整行删除/替换时，操作范围应覆盖整个 `[fromLine, toLine]` 块；只删除或替换 `fromLine` 而留下隐藏内容，不属于该例外，必须先展开。

Undo/Redo 不自动恢复折叠状态。一次编辑造成的展开，在 Undo 后仍保持展开；Undo/Redo 自身不按交互式输入再次触发展开规则。

## 6. 推荐实施顺序

1. 为 SyntaxState 增加有序分隔符事件，并让 CodeBlock 保存 `fromCh/toCh`。
2. 修正增量重扫、状态比较、块移动和失效处理，确保字符位置可靠。
3. 统一结束行可见性、占位符、行宽、鼠标和光标映射。
4. 实现两种显示模式下的原子光标移动，并隔离虚拟位置与 Document 位置。
5. 为 DocumentChange 补充字符范围和整行标记，在每个视图的 contentChanged 中、fold rescan 前实现展开判断。
6. 实现整行删除/替换例外，并验证批量修改经 recordChange 合并后仍保持正确。

## 7. 测试清单

### 显示与状态

- `}` 后无字符、空格、Tab、注释、`;` 和 `else`；
- `} else {`、同行多个块、嵌套块、预处理折叠；
- 无可隐藏内容的块；
- 占位符颜色、无额外下划线、行宽和水平滚动范围；
- 编辑尾部后可见性、字符位置和行映射及时更新。

### 光标

- 两种显示模式下的左右键往返；
- 从下一可见行按左键；
- 鼠标点击占位符两端；
- 上下移动、Home/End、Shift 选区；
- 不停在省略号中间；
- 虚拟位置不会被传给 Document 写入接口。

### 编辑

- `{` 前插入与删除；
- `{` 后输入；
- `}` 后输入、Delete 和 Backspace；
- Enter、粘贴、拖放、选区替换和跨行合并；
- 尾部无内容变有内容、有内容变无内容、删除但未删光；
- 触及折叠块任意部分的选区编辑；
- 整行删除/替换及其嵌套编辑入口；
- 每种操作后的文档内容、光标位置、折叠状态和 Undo/Redo。

## 8. 方案审核结论

本方案已针对以下容易遗漏的实现问题作出约束：

- 仅增加 `fromCh/toCh` 而不保存同行事件顺序，会无法正确处理 `} else {` 和嵌套块，因此采用有序事件。
- 仅在 SyntaxState 中保存位置而不更新 `equals()` 和增量重扫，会使用失效位置，因此这些属于同一项基础工作。
- 直接放宽 `validInDoc()` 会让虚拟位置泄漏到 Document 操作，因此必须分离光标校验。
- 只判断编辑范围而不判断编辑后的尾部状态，会导致结束行突然隐藏或显示，因此需要操作后状态判断。
- 仅按命令名豁免整行操作，会掩盖部分删除折叠块的问题，因此例外必须按实际覆盖范围判断。
- 光标、显示、行宽和编辑若分别计算折叠文本，会再次产生不一致，因此必须共用折叠映射。

在这些约束得到实现和测试覆盖之前，不应把该功能视为完成。
